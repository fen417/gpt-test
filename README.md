# SECTOR 09

Браузерный 3D-шутер про пехотный бой за территорию. Самостоятельный игровой прототип, вдохновлённый командными военными шутерами. Без техники, установки и регистрации.

**Играть:** https://fen417.github.io/gpt-test/

## Что работает

- Промышленная карта площадью 200 × 200 м с укрытиями и тремя точками захвата.
- Две команды, 300 билетов, победа через удержание территории и потери противника.
- Четыре класса: штурмовик, медик, поддержка и разведчик; разные оружие, магазины, темп огня и способности.
- Прицеливание, отдача, перезарядка, ограниченные боеприпасы, гранаты, бег, приседание и прыжок.
- Попадания с проверкой препятствий, урон в голову, восстановление здоровья и возрождение на базе или своей неоспариваемой точке.
- Боты ищут путь, захватывают точки, стреляют и возвращаются после гибели.
- Сетевые комнаты по коду и отдельный авторитетный WebSocket-сервер.
- Миникарта, счёт, журнал устранений, процедурные звук, модели и эффекты.

Это ранняя версия: здесь нет разрушаемых зданий, входных интерьеров, поднятия погибших союзников, управляемых отрядов, прогрессии и полноценного античита. Стабильные 16 игроков в разных сетях ещё требуют нагрузочных испытаний.

## Как играть

1. Открой игру в актуальном настольном Chrome, Edge или Firefox с аппаратным ускорением.
2. Введи позывной и выбери класс.
3. **«На поле боя»** запускает локальный матч с 15 ботами.
4. Захватывай A, B и C: стой в зоне без противника. Удержание большинства точек уменьшает билеты врага.

| Клавиша | Действие |
| --- | --- |
| WASD | Движение |
| Мышь | Обзор |
| ЛКМ / ПКМ | Огонь / прицел |
| Shift | Бег |
| C / левый Ctrl | Присесть |
| Пробел | Прыжок |
| R | Перезарядка |
| Q | Способность класса |
| G | Граната |
| Tab | Таблица игроков |
| Esc | Меню |

Если встроенный просмотрщик блокирует захват мыши, выбери **«Играть без захвата мыши»**. В этом режиме обзор работает при движении мыши с зажатой ПКМ или стрелками клавиатуры. Для привычного FPS-управления открой ссылку в отдельной вкладке браузера.

Способности: штурмовик восстанавливает здоровье, медик лечит находящихся рядом союзников, поддержка пополняет резерв патронов, разведчик обнаруживает ближайших врагов на миникарте. Способности имеют перезарядку.

## Игра с друзьями на GitHub Pages

Хозяин нажимает **«Создать комнату»** и передаёт шестизначный код. Остальные выбирают **«Войти по коду»**. Матч рассчитывает браузер хозяина; обмен состоянием идёт через WebRTC. PeerJS Cloud используется для поиска соединения.

Хозяин должен держать вкладку открытой и активной. При его выходе комната закрывается. Публичный сервис сигнализации и прямое WebRTC-соединение зависят от доступности сервиса, NAT и сети: подключение не гарантируется во всех сетях. Собственный TURN-сервер в комплект не входит. При невозможности соединения игра показывает ошибку; для постоянного матча используй выделенный сервер.

## Локальная разработка

Нужен Node.js 22 или новее.

```sh
npm ci
npm run dev
```

Открой напечатанный Vite адрес. Сборка и проверки:

```sh
npm test
npm run build
npm run preview
```

## Выделенный сервер

```sh
npm ci
npm run build
npm start
```

Сервер обслуживает клиент на `http://localhost:8080` и WebSocket на `ws://localhost:8080`. В меню раскрой **«Выделенный сервер»** и введи адрес. Для клиента на HTTPS (включая GitHub Pages) нужен публичный `wss://` с доверенным сертификатом; незашифрованный `ws://` допустим только локально.

Переменные окружения: `PORT` (8080), `BOTS` (12), `MAX_PLAYERS` (16). Проверка готовности: `GET /health`. Сервер самостоятельно возобновляет раунд через 12 секунд после победы.

Можно развернуть приложенный Dockerfile на хостинге с поддержкой долгих WebSocket-соединений. `render.yaml` — конфигурация для Render; сервер в этом репозитории **не означает**, что отдельный облачный сервер уже оплачен или запущен.

## Публикация на GitHub Pages

В репозитории: **Settings → Pages → Source → GitHub Actions**. Workflow `.github/workflows/pages.yml` устанавливает зависимости, запускает тесты, собирает Vite и публикует `dist`. Push в `main` обновляет игру. Относительные пути сборки поддерживают размещение в `/gpt-test/`.

GitHub Pages размещает статический клиент. Node.js-сервер из папки `server` на GitHub Pages не исполняется; сетевые комнаты используют браузер хозяина либо отдельно размещённый сервер.

## Архитектура и проверки

- `shared/world.js`: единая карта, параметры оружия и классов.
- `shared/simulation.js`: расчёт движения, попаданий, ботов, точек и билетов.
- `src/renderer.js`: Three.js, процедурные модели, оружие, эффекты и освещение.
- `src/network.js`: PeerJS/WebRTC и транспорт выделенного сервера.
- `src/main.js`: управление, меню, HUD, миникарта и игровые переходы.
- `server/index.js`: HTTP/WebSocket, проверка команд и рассылка состояния.

Автотесты проверяют попадания и укрытия, захват и оспаривание точек, возрождение, перезарядку, способности, гранаты, ботов, фильтрацию входных данных и взаимодействие двух настоящих WebSocket-клиентов. Они не заменяют испытания WebRTC на разных устройствах и сетях.

Модели и текстуры создаются кодом; игровых материалов Battlefield нет. Шрифт загружается через Google Fonts с системными запасными шрифтами. Код проекта — MIT, зависимости распространяются по своим лицензиям.
